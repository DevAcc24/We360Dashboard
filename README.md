# Моя статистика we360

Невеликий застосунок для Windows, який показує **вашу власну** статистику з локальної бази та логів десктоп-агента we360. Працює з іконки в треї й відкриває дашборд у браузері.

Застосунок лише **читає** файли агента: копіює базу в тимчасову папку, переносить записи у власний архів і нічого не змінює в даних агента. Нічого не надсилається в мережу: сторінка доступна тільки на `127.0.0.1`.

## Що показує

- відстежений час по днях: активний і неактивний;
- мапу робочого часу з кроком 5 хвилин, разом із періодами блокування екрана та сну;
- середню активність за годинами доби та днями тижня;
- програми, сайти (домени) та заголовки вікон за часом у фокусі;
- події безпеки, які записав агент (наприклад, виявлення mouse jiggler);
- таблицю по днях із кількістю натискань клавіш і кліків.

Період можна обрати кнопками (1, 7, 14 чи 30 останніх днів або все) чи задати датами. Окремо можна показати лише будні й не враховувати в середніх короткі дні (менше 2 годин).

Це сирі дані без оцінок. Продуктивність, категорії програм і правила обліку часу we360 рахує на сервері, тому цифри на офіційному дашборді можуть відрізнятися.

Агент з часом видаляє старі записи з бази. Застосунок зберігає їх у власному архіві (`data\archive.db`), тож історія накопичується. Час, якого в базі вже немає (або ще не було, як у день встановлення агента), відновлюється з логів агента (`log_*.log`) з кроком 5 хвилин, але без розбивки за програмами. Проміжки, які покриває база, з логів не додаються, тож час не рахується двічі.

## Вимоги

- Windows 10/11 x64 (використовується вбудований у Windows `winsqlite3.dll`);
- для збірки: [.NET SDK 10](https://dotnet.microsoft.com/download).

Готовий exe самодостатній, встановлювати .NET для запуску не потрібно.

## Збірка

```powershell
dotnet publish app/We360Dashboard -c Release -o dist
```

Результат: `dist\We360Dashboard.exe`, один файл.

### Автоматичні релізи

Після кожного push у `main` GitHub Actions (`.github/workflows/release.yml`) запускає тести, якщо вони є, збирає exe і створює GitHub Release `v<версія>` з `We360Dashboard.exe`. Версія має вигляд `<VersionPrefix>.<номер запуску>`: `VersionPrefix` (наприклад, `1.0`) задається в `We360Dashboard.csproj`, а номер запуску GitHub підставляє сам. Локальна збірка отримує номер `0`. Зміни лише в `*.md` чи `.gitignore` релізу не створюють. Запустити збірку вручну можна на вкладці **Actions** → **Build and release** → **Run workflow**.

## Використання

1. Запустіть `We360Dashboard.exe`. У треї з'явиться іконка.
2. Клацніть по ній лівою кнопкою, і в браузері відкриється дашборд.
3. Якщо базу агента не знайдено автоматично, клацніть правою кнопкою → **«Вибрати папку з даними агента…»** і вкажіть папку, де лежить `zs.db`.

Повторний запуск exe не створює другого екземпляра, а просто відкриває сторінку.

Меню іконки дає змогу також скопіювати адресу сторінки, відкрити `settings.json` і папку застосунку.

### Режим без інтерфейсу

Для перевірки можна згенерувати HTML-файл без запуску трею:

```powershell
We360Dashboard.exe --build <папка з zs.db> <вихідний.html> [archive.db]
```

## Налаштування

Застосунок портабельний: усе зберігається в підпапці `data` поруч з exe.

| Файл | Призначення |
|---|---|
| `data\settings.json` | налаштування |
| `data\archive.db` | накопичений архів даних |
| `data\url.txt` | адреса запущеного екземпляра |

Поля `settings.json`:

| Поле | Типово | Опис |
|---|---|---|
| `DataFolder` | `%APPDATA%\ai.zs\zs` | папка агента з `zs.db` |
| `LogsFolder` | `DataFolder\logs` | папка з `log_*.log` |
| `Port` | `47360` | локальний порт; якщо зайнятий, береться будь-який вільний |
| `Token` | випадковий | секретна частина адреси сторінки |
| `TimeZone` | зона комп'ютера | часовий пояс для відображення, наприклад `Europe/Kyiv` або `FLE Standard Time` |

Зміни в `settings.json` підхоплюються без перезапуску. Якщо у файлі помилка, застосунок показує попередження в треї, працює з типовими значеннями (адреса сторінки при цьому лишається тією самою) і не перезаписує файл, доки його не виправлять. Поточна часова зона показана вгорі сторінки.

## Безпека

- HTTP-сервер слухає лише `127.0.0.1`;
- сторінка доступна тільки за адресою з випадковим токеном (`http://127.0.0.1:<порт>/<токен>/`);
- перевіряється заголовок `Host` (захист від DNS rebinding), приймаються лише `GET`/`HEAD`;
- сувора Content-Security-Policy: сторінка не завантажує жодних зовнішніх ресурсів.

## Конфіденційність

Бази, логи, архів і згенеровані сторінки містять особисту інформацію (заголовки вікон, адреси сайтів, графік роботи). Вони виключені через `.gitignore`. Не додавайте їх у репозиторій і не публікуйте.

## Структура

```
app/We360Dashboard/
  Program.cs                точка входу, режим --build, один екземпляр
  TrayContext.cs            іконка в треї, меню, кешування сторінки
  LocalServer.cs            мінімальний HTTP-сервер на 127.0.0.1
  DataBuilder.cs            синхронізація з базою й логами агента, побудова JSON
  AppSettings.cs            налаштування та шляхи
  dashboard_template.html   сторінка дашборда (графіки на SVG, без залежностей)
```
